# Aparté 1.2.0 — dictées récupérables et enregistrement Linux fiabilisé

Cette version permet de récupérer une dictée après un échec de traitement et
améliore le diagnostic des refus d'enregistrement sous Linux.

## Nouveautés

- **Récupérer une dictée en échec pendant une heure** depuis l'interface ou
  `aparte recover` : réessayer, retrouver le texte brut lorsqu'il est disponible,
  ou supprimer la capture.
- Le résultat récupéré s'affiche séparément. Remplacer le texte de l'éditeur
  demande confirmation ; aucun collage dans une autre application n'est lancé
  automatiquement.
- Les captures restent locales, dans un dossier privé. Leur délai de
  récupération ne se prolonge pas à chaque réessai. Le nettoyage fonctionne
  aussi pour les sauvegardes interrompues.

## Corrections

- Les refus du micro conservent maintenant le diagnostic ALSA, l'heure, le
  périphérique et le code retour. Un périphérique indisponible n'est plus
  systématiquement annoncé comme « occupé ».
- Les transitions d'enregistrement sont protégées contre les appels
  concurrents. Un démarrage interrompu nettoie son enregistreur ; un arrêt
  non confirmé conserve le suivi de la capture.
- Les corrections et raccourcis contenant des antislashs sont traités comme
  du texte littéral, sans casser la mise en forme des dictées.
- Les lectures HTTP privées valident le nom d'hôte. Les erreurs disque pendant
  un envoi audio ne bloquent plus les transcriptions suivantes.

## Mise à jour

Dans Aparté, ouvrir **Configuration**, puis vérifier les mises à jour et
installer cette version. Redémarrer l'application après une mise à jour manuelle.
Les réglages existants, notamment la langue Auto, restent conservés.

Le délai de récupération est d'une heure. L'effacement physique a lieu lors
du nettoyage périodique tant que l'application tourne, ou au prochain lancement
sinon ; un réessai actif peut terminer. Si le stockage de récupération échoue,
l'original est conservé hors de ce nettoyage, comme avec `--keep-audio`.

## Validation

317 tests locaux passent. Le parcours de récupération a aussi été vérifié
dans Chromium avec le vrai serveur HTTP et un transcripteur simulé.
Le comportement après une vraie sortie de veille reste à confirmer à l'usage :
cette version améliore le diagnostic, sans prétendre en avoir établi la cause.
